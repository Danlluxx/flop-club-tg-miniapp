# Смены сотрудников и таблица зарплат

Админ вносит часы сотрудников за турнир, бот раз в сутки дописывает их в Excel-таблицу зарплат и присылает владельцу обновлённый файл.

## Как устроено

- Основной файл «ЗП FLOP CLUB.xlsx» лежит в БД (`PayrollWorkbook`, ключ `master`). Таблица со своими формулами, листы `Смены`, `Сотрудники`, `Выплаты`, `Периоды` — источник правды по ставкам и выплатам.
- Смены лежат в `StaffShift` (турнир, сотрудник, дата турнира по Барнаулу, начало/конец, перерыв, часы вручную, статус, `exportedAt`). `exportedAt` null = ещё не в файле.
- `apps/api/src/services/payrollWorkbook.ts`: `appendShifts` правит XML листа `Смены` напрямую (jszip), а не пересохраняет книгу через exceljs: иначе пропадают выпадающие списки (x14 dataValidation) со списком сотрудников. Пишет B, D, E, F, G, H, M, N в первую свободную строку после последней заполненной (шаблонные строки 6–2005 уже с формулами). Формулы Excel пересчитает сам (`fullCalcOnLoad`).
- `exportPendingShifts` дописывает все новые смены, сохраняет результат как новый основной файл и ставит `exportedAt`. Всё в одной транзакции, под очередью в процессе.
- Слияние при загрузке файла (приложение или бот → `saveMasterWorkbook` → `syncShiftsFromWorkbook` → `planMerge`): строки листа `Смены` с `IMPORT_FROM` (2026-09-01) сопоставляются с записанными в таблицу сменами приложения по ключу `shiftKey` (дата, сотрудник, время, перерыв, часы, штраф, статус; без комментария). Идентичные остаются; оставшиеся пары по (дата, сотрудник) считаются правкой из Excel, файл побеждает; лишние в файле добавляются в приложение; лишние в приложении (файл старый) возвращаются в очередь (`exportedAt` null) и сразу дописываются в файл, бот присылает итоговый. Ещё не записанные смены приложения не трогаются. Смена привязывается к первому турниру того дня; строки без турнира считаются в `skipped`. Загрузка идемпотентна. Ограничение: строку, удалённую в Excel, слияние вернёт, пока она есть в приложении, поэтому записанные смены удаляются в приложении (владелец, `deleteShift`: чистит и строку в файле, `removeShiftRows`).
- Всё, что переписывает основной файл (скачивание, загрузка, удаление), идёт через одну очередь `serialize`.
- Имя сотрудника проверяется по листу `Сотрудники` основного файла; уволенные в списке не показываются.
- Экран: `apps/web/src/pages/admin/PayrollPage.tsx`, `/admin/payroll`; выбор турнира — календарь `components/PayrollCalendar.tsx` (список турниров с `IMPORT_FROM` до +30 дней). API: `apps/api/src/routes/payroll.ts`, `/api/admin/payroll/*`.

## Аналитика

- Экран `pages/admin/PayrollAnalyticsPage.tsx` (`/admin/payroll/analytics`, ссылка с «Смен» только владельцу), API `GET /api/admin/payroll/analytics?period=day|week|month&date=` (`requireAnalyticsOwner`), логика в `services/payrollAnalytics.ts`.
- Считаются только смены «Отработана» за период по `workDate` (неделя Пн–Вс). Заработок = часы × ставка из листа `Сотрудники` (колонка G) или ставка за смену (H) при типе оплаты «За смену», как формула колонки L таблицы. Премии/штрафы (`StaffShift.adjustment` ↔ колонка K) считаются отдельно: `pay` (по часам), `adjustment`, `earned` = pay (+ adjustment при `fines=with`). Запись без часов, только со штрафом/вычетом, допустима (в таблицу пишется с H=0, чтобы не было ⚠). В ответе есть список `adjustments` (дата, сотрудник, сумма, комментарий). Ставки читаются из основного файла при каждом запросе (`readRoster`).

## Бот (`services/payrollBot.ts`)

- Планировщик каждые 10 минут; после `PAYROLL_REPORT_HOUR` (6:00 Барнаул) раз в сутки: если есть новые смены, дописывает и отправляет файл адресатам `PAYROLL_TELEGRAM_USERNAMES` (по умолчанию `danlluxx`; им нужно хоть раз запустить бота, иначе нет `TelegramSubscriber`). Без новых смен ничего не шлёт.
- Если отправка упала, файл уже сохранён: следующий запуск шлёт тот же файл, смены второй раз не пишутся (`payroll:unsent`, `payroll:lastSentDate` в `TelegramBotState`).
- Владелец присылает боту исправленный `.xlsx` в личку: он сливается с приложением и становится основным файлом (`handlePayrollMessage` → `handleDocument`, вызывается из polling в `telegramSubscribers.ts`).
- Кнопки (`services/payrollFlow.ts`): `/меню` показывает постоянную клавиатуру («➕ Запись», «↩️ Отменить», «📄 Таблица»); «➕ Запись» открывает одну карточку, которая редактируется на месте: тип (штраф/премия/ре-энтри/адон/смена) → сотрудник → сумма или часы → подтверждение (кнопки «Вчера/Сегодня», «Записать», «Отмена»; текстом можно прислать сумму, дату или причину). После записи кнопки «Отменить запись» и «Ещё запись». Состояние карточки: `TelegramBotState` `payroll:flow:<chatId>`. Нужен `callback_query` в `allowed_updates` polling (`telegramSubscribers.ts`). Общие функции записи/отмены: `payrollEntries.ts`, вызовы Telegram: `payrollTelegram.ts`.
- Команды владельца в личке (`services/payrollCommands.ts`, разбор; исполнение в `payrollBot.ts`): `/штраф Имя сумма [причина]`, `/реэнтри Имя [сумма]` (по умолчанию 500), `/адон Имя [сумма]` (1000), `/премия Имя сумма [причина]`, `/смена Имя 19:00 23:30` или часы, `/отмена`, `/таблица`, `/помощь`; дата необязательна (`12.11`, `вчера`). Имя ищется по списку сотрудников таблицы (точно, по началу, по вхождению; имена из нескольких слов вроде «Никита 1» поддержаны). Запись идёт на турнир клубного дня (`clubDay`: день меняется в 06:00 Барнаула) и попадает в таблицу в ближайшую рассылку или по `/таблица`. Стек для `/отмена` лежит в `TelegramBotState` (`payroll:undo:<chatId>`). Неизвестные команды игнорируются (не мешать `/start`).

## Правила и ловушки

- Файл и ставки видит только владелец (`requireAnalyticsOwner`): скачивание и замена файла. Админы видят только смены и имена сотрудников, без ставок.
- Скачивание тоже дописывает смены: выданный файл всегда основной. Старую копию загружать безопасно: слияние вернёт недостающие записи в файл.
- Смену, уже попавшую в таблицу, из приложения нельзя изменить; удалить может владелец (убирает и строку в файле).
- Выплаты, ставки, премии/штрафы и новых сотрудников правят в таблице и присылают боту.
- Тесты: `apps/api/tests/payroll-workbook.test.mjs` (синтетическая книга, личный файл не в репозитории).
