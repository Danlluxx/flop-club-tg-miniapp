# Смены сотрудников и таблица зарплат

Админ вносит часы сотрудников за турнир, бот раз в сутки дописывает их в Excel-таблицу зарплат и присылает владельцу обновлённый файл.

## Как устроено

- Основной файл «ЗП FLOP CLUB.xlsx» лежит в БД (`PayrollWorkbook`, ключ `master`). Таблица со своими формулами, листы `Смены`, `Сотрудники`, `Выплаты`, `Периоды` — источник правды по ставкам и выплатам.
- Смены лежат в `StaffShift` (турнир, сотрудник, дата турнира по Барнаулу, начало/конец, перерыв, часы вручную, статус, `exportedAt`). `exportedAt` null = ещё не в файле.
- `apps/api/src/services/payrollWorkbook.ts`: `appendShifts` правит XML листа `Смены` напрямую (jszip), а не пересохраняет книгу через exceljs: иначе пропадают выпадающие списки (x14 dataValidation) со списком сотрудников. Пишет B, D, E, F, G, H, M, N в первую свободную строку после последней заполненной (шаблонные строки 6–2005 уже с формулами). Формулы Excel пересчитает сам (`fullCalcOnLoad`).
- `exportPendingShifts` дописывает все новые смены, сохраняет результат как новый основной файл и ставит `exportedAt`. Всё в одной транзакции, под очередью в процессе.
- Обратный импорт: при каждой загрузке основного файла (приложение или бот, `saveMasterWorkbook` → `syncShiftsFromWorkbook`) смены с `IMPORT_FROM` (2026-09-01) из листа `Смены` пересоздаются в `StaffShift` с `exportedAt`; ещё не записанные в файл смены приложения не трогаются. Смена привязывается к первому турниру того дня (по `startsAt`); строки без турнира в этот день, а также строки без времени и без ненулевых часов (штрафы/премии) пропускаются и считаются в `skipped`. Импорт идемпотентен.
- Имя сотрудника проверяется по листу `Сотрудники` основного файла; уволенные в списке не показываются.
- Экран: `apps/web/src/pages/admin/PayrollPage.tsx`, `/admin/payroll`; выбор турнира — календарь `components/PayrollCalendar.tsx` (список турниров с `IMPORT_FROM` до +30 дней). API: `apps/api/src/routes/payroll.ts`, `/api/admin/payroll/*`.

## Бот (`services/payrollBot.ts`)

- Планировщик каждые 10 минут; после `PAYROLL_REPORT_HOUR` (6:00 Барнаул) раз в сутки: если есть новые смены, дописывает и отправляет файл адресатам `PAYROLL_TELEGRAM_USERNAMES` (по умолчанию `danlluxx`; им нужно хоть раз запустить бота, иначе нет `TelegramSubscriber`). Без новых смен ничего не шлёт.
- Если отправка упала, файл уже сохранён: следующий запуск шлёт тот же файл, смены второй раз не пишутся (`payroll:unsent`, `payroll:lastSentDate` в `TelegramBotState`).
- Владелец присылает боту исправленный `.xlsx` в личку: он становится основным файлом (`handlePayrollDocument`, вызывается из polling в `telegramSubscribers.ts`).

## Правила и ловушки

- Файл и ставки видит только владелец (`requireAnalyticsOwner`): скачивание и замена файла. Админы видят только смены и имена сотрудников, без ставок.
- Скачивание тоже дописывает смены: выданный файл всегда основной. Старую копию загружать нельзя, она сотрёт записанные смены (в UI и в подписи бота есть предупреждение).
- Смену, уже попавшую в таблицу, из приложения не изменить и не удалить (правка в самой таблице).
- Выплаты, ставки, премии/штрафы и новых сотрудников правят в таблице и присылают боту.
- Тесты: `apps/api/tests/payroll-workbook.test.mjs` (синтетическая книга, личный файл не в репозитории).
